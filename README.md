# NeuroStream Studio

Настольное приложение для управления TikTok LIVE трансляциями: TikTok LIVE + AxelChat,
независимая озвучка (TTS), конструктор триггеров, управление IoT-устройствами и
алерты для OBS Studio через Browser Source.

Стек: **Electron + Node.js + Express + Socket.io + SQLite (better-sqlite3) + tiktok-live-connector**.

---

## 1. Требования

- **Node.js 20 или новее** (проверялось на Node 22) — https://nodejs.org
- **Windows 10/11** для итоговой сборки `.exe` (разработку и `npm run dev` можно запускать и на другой ОС,
  но production-сборка выполняется под Windows через `electron-builder --win`).
- Python и инструменты сборки C++ обычно не требуются — `better-sqlite3` устанавливается через
  готовый бинарник, а `electron-rebuild` (см. ниже) пересобирает его под ABI Electron автоматически.

## 2. Установка

```bash
npm install
```

Эта команда установит все зависимости и автоматически выполнит `electron-builder install-app-deps`
(хук `postinstall` в `package.json`), который пересобирает нативный модуль `better-sqlite3`
под версию Electron, указанную в `package.json`.

Если по какой-то причине автоматическая пересборка не сработала — выполните вручную:

```bash
npm run rebuild
```

## 3. Запуск в режиме разработки

```bash
npm run dev
```

Откроется главное окно панели управления. Встроенный сервер поднимается на локальном порту
(по умолчанию `47823`, при занятости — следующий свободный) и обслуживает:

- `http://127.0.0.1:<порт>/index.html` — панель управления (открывается автоматически)
- `http://127.0.0.1:<порт>/overlay.html` — страница для **OBS Browser Source** (добавьте её
  как источник "Браузер" в OBS; адрес также отображается во вкладке *Media Library*)
- `http://127.0.0.1:<порт>/tts-host.html` — служебная страница озвучки (открывается скрытым окном
  автоматически, вручную открывать не нужно)

## 4. Подключение к TikTok LIVE

1. Во вкладке **Главная** укажите `@uniqueId` стримера (без `@`).
2. Библиотека `tiktok-live-connector` v2 подписывает WebSocket-запросы через сервис
   **Euler Stream** (eulerstream.com). Без ключа доступен бесплатный общий лимит запросов —
   этого достаточно для тестирования, но при долгих стримах или частых переподключениях
   рекомендуется получить бесплатный/платный `signApiKey` на сайте Euler Stream и указать
   его в соответствующем поле — это снимает ограничение по лимиту.
3. Приложение автоматически переподключается при обрыве связи (экспоненциальная задержка
   3с → 6с → 12с … до 60с).
4. **Важно понимать: это не «вход в аккаунт».** TikTok не выдаёт сторонним разработчикам
   официальный API для чтения LIVE-чата, поэтому `tiktok-live-connector` подключается
   напрямую к открытым данным уже идущей трансляции — без логина и пароля. Из этого следует
   главное условие: **на момент нажатия «Подключиться» трансляция должна реально идти**.
   Если стрим не запущен, попытка подключения закончится ошибкой
   «Стример @… сейчас не в эфире» — теперь она отображается прямо под формой на вкладке
   Главная, а не только в журнале.
5. На вкладке Главная есть кнопка **«Проверить, в эфире ли»** — мгновенно (один HTTP-запрос,
   без полного подключения) показывает, идёт ли трансляция прямо сейчас. Проверяйте ей перед
   подключением, если не уверены.

### Ответ в чат текстом (не только озвучка)

Помимо чтения и озвучки, приложение умеет **отправлять текстовые сообщения в чат TikTok
от вашего имени** — например, автоматический ответ на донат. Это делает новый тип действия
триггера **«Ответ в чат (только TikTok)»** в конструкторе триггеров: укажите шаблон текста
(с переменными `{user}`, `{gift}`, `{text}` и т.д. — как в шаблонах озвучки).

Так как отправка сообщения выполняется от лица настоящего аккаунта, для неё нужна
авторизованная сессия — TikTok не даёт делать это анонимно. На вкладке Главная под полем
signApiKey есть два поля для **сессионных cookie**: `sessionid` и `tt-target-idc`. Как их
получить:

1. Откройте tiktok.com в браузере и войдите в тот аккаунт, от имени которого должны
   отправляться сообщения.
2. Откройте инструменты разработчика (F12) → вкладка **Application** (в Chrome/Edge) или
   **Storage** (в Firefox) → **Cookies** → `https://www.tiktok.com`.
3. Найдите строки `sessionid` и `tt-target-idc`, скопируйте их значения в соответствующие
   поля в NeuroStream Studio.

**Это чувствительные данные, равносильные паролю от аккаунта** — храните их только в этой
программе (они остаются локально в базе данных на вашем компьютере и никуда, кроме серверов
TikTok, не отправляются) и никому их не передавайте. Раз в некоторое время TikTok обновляет
`sessionid` — если ответы в чат перестали отправляться при том, что чтение чата работает,
скорее всего это устаревшая cookie, которую нужно взять заново.

Без этих полей чтение и озвучка чата работают как обычно — они не обязательны, нужны только
для действия «Ответ в чат».

**Ограничение:** отправка сообщений сейчас реализована только для TikTok — у платформ,
подключённых через AxelChat (YouTube/Twitch/Kick/VK и т.д.), нет документированного способа
отправки сообщений через API AxelChat, это может измениться только с отдельной нативной
интеграцией под каждую платформу.

### Вход через браузер (автоматическое получение сессионных cookie)

Вместо ручного копирования cookie из DevTools можно нажать кнопку **«🌐 Войти через
браузер»** рядом с полями сессии — откроется настоящее окно входа TikTok (обычная страница
tiktok.com/login в отдельном окне Electron). Логин, пароль и код подтверждения вы вводите
сами, как в любом браузере — ничего не автоматизируется. Как только TikTok выставит cookie
входа, оба поля (`sessionid` и `tt-target-idc`) заполнятся автоматически, окно закроется, и
останется только нажать «Подключиться».

**Важно понимать, что этот вход решает, а что нет:** он относится только к действию
«Ответ в чат» (отправка сообщений от вашего имени). На чтение чата и подключение к трансляции
это не влияет и ошибку `SignAPIError`/подобные не исправляет — эта ошибка про другое
(см. следующий раздел).

### Диагностика ошибок при подключении (SignAPIError и похожие)

Если под формой TikTok появляется ошибка вида «Ошибка сервера подписи TikTok (Sign API)» —
это **не проблема логина и не обязательно означает, что трансляция не запущена** (для этого
есть отдельное сообщение «Стример @… сейчас не в эфире»). Это означает, что не удалось
получить корректную подпись WebSocket-подключения от **стороннего сервиса Euler Stream**,
через который работает вся библиотека `tiktok-live-connector` — TikTok не даёт официального
способа читать LIVE-чат, и Euler Stream — общепринятое решение, которым пользуется вся
экосистема таких инструментов, а не что-то специфичное для этой программы.

С последним обновлением текст такой ошибки стал куда подробнее — под формой и в журнале
(Logs & Settings) теперь видно точную причину от самого Euler Stream, а не общую фразу.
Частые причины и что делать:

- **`SignatureRateLimitError`** — превышен бесплатный лимit запросов. Получите ключ на
  eulerstream.com (бесплатная регистрация уже снимает часть ограничений) и укажите его в
  поле signApiKey.
- **`PremiumFeatureError`** — конкретная операция требует платного тарифа Euler Stream.
  Проверьте тариф вашего ключа в личном кабинете eulerstream.com.
- **`SignatureMissingTokensError`** — сервер подписи вернул неполный ответ; часто означает,
  что указанный signApiKey недействителен/истёк, либо у Euler Stream временный сбой.
- **Прочие ошибки Sign API** — возможна временная недоступность серверов TikTok/Euler Stream,
  либо блокировка исходящих соединений антивирусом/файрволом на вашем компьютере — попробуйте
  временно отключить их для проверки.

Если ключ signApiKey уже указан и ошибка сохраняется — стоит проверить его статус
непосредственно в личном кабинете на eulerstream.com (активен ли, остались ли лимиты/кредиты).

### Не получается подключиться? Порядок диагностики

1. Откройте вкладку **Главная** — под формой TikTok теперь всегда показан точный текст
   последней ошибки.
2. Проверьте, что трансляция **сейчас идёт** и `@uniqueId` указан без опечаток и без `@`.
3. Если ошибка про лимит запросов (`SignatureRateLimitError`) — получите `signApiKey` на
   eulerstream.com и укажите его в форме подключения.
4. Если ничего не помогает — можно подключить TikTok в обход `tiktok-live-connector`, через
   **AxelChat** (см. следующий раздел): AxelChat поддерживает TikTok как одну из платформ,
   и часто его реализация оказывается более стабильной на проблемных сетях/регионах.
   В этом случае не включайте одновременно оба способа подключения к одному и тому же
   аккаунту — сообщения будут дублироваться.

## 5. Подключение к AxelChat — и почему это решает вопрос YouTube/Twitch/Kick/VK

[AxelChat](https://github.com/3dproger/AxelChat) — отдельное открытое приложение-агрегатор
чатов. Ключевой момент: **AxelChat уже умеет подключаться к YouTube, Twitch, Kick,
VK Видео Трансляциям, TikTok и ещё почти четырём десяткам платформ** — авторизация для
каждой из них настраивается внутри самого AxelChat (обычно через открытие браузера или
ввод токена — у каждой платформы свой способ, интерфейс AxelChat подсказывает какой).
NeuroStream Studio подключается к AxelChat один раз и через него получает **уже объединённый
поток** сообщений, лайков, подписок и donate-уведомлений со всех платформ, которые вы
включили внутри AxelChat, размеченный по названию платформы (`serviceId`).

**Это значит: чтобы одновременно озвучивать YouTube, Twitch, Kick и VK Видео — не нужно
ждать отдельной разработки под каждую платформу.** Установите AxelChat, подключите в нём
нужные аккаунты (по инструкции самого AxelChat для каждой платформы) — и все их события
начнут приходить в NeuroStream Studio автоматически через уже работающую интеграцию.

1. Установите и запустите AxelChat, подключите в нём нужные платформы.
2. В настройках AxelChat включите **Settings → Developers → WebSocket server**
   (по умолчанию слушает `127.0.0.1:8356`) — если этого не сделать, подключение будет
   получать ошибку `ECONNREFUSED`, которая теперь тоже отображается прямо в интерфейсе.
3. Во вкладке **Главная** укажите хост/порт (по умолчанию уже подставлены `127.0.0.1:8356`)
   и нажмите «Подключиться». Ниже появится таблица «Зрители по платформам» — суммарно и по
   каждой включённой в AxelChat платформе.

### Про ссылки вида `.../widgets/default/bundle1/host/index.html?widget=messages`

Это не API для программ, а **готовые HTML-страницы самого AxelChat** — визуальные виджеты,
предназначенные для добавления в OBS как источник «Браузер» (например, чтобы показать чат
поверх экрана). Внутри они используют тот же WebSocket (`ws://127.0.0.1:8356`), к которому
подключается NeuroStream Studio напрямую — то есть наша интеграция обращается к тому же
источнику данных, но напрямую и с полным контролем (без необходимости показывать/парсить
HTML-страницу). Если вам отдельно нужен визуальный чат поверх трансляции в OBS — эти ссылки
по-прежнему можно добавить как второй источник «Браузер» в OBS, они не конфликтуют с работой
NeuroStream Studio.

### Ограничение на озвучку донатов/подписок через AxelChat

AxelChat присылает подписки, донаты и подобные события как специально оформленные сообщения
в общем потоке чата (с цветными тегами вроде «STREAMER»/суммой доната и т.д.), а не как
отдельный технический тип события для каждой платформы. Сейчас NeuroStream Studio озвучивает
и обрабатывает все такие сообщения как обычный чат — это уже работает и его можно
использовать в Trigger Builder по ключевым словам (например, триггер на слово «Donate» или
конкретную сумму в тексте). Более точное автоматическое распознавание «это донат, а не чат»
для каждой платформы через AxelChat — это отдельная доработка, которая потребует проверки
на реальных данных с ваших подключённых аккаунтов.

## 6. Качество голосов озвучки

Встроенный синтез речи использует голоса, установленные в Windows (через Web Speech API
Chromium) — их качество полностью зависит от того, какие голоса стоят в системе.

**Быстрое улучшение без программирования (бесплатно):**
Windows 10/11 позволяет установить более естественные «Neural»-голоса:
`Параметры → Время и язык → Речь → Управление голосами → Добавить голоса` → добавьте
русский язык/голос с пометкой «Natural» (например, «Ирина» / «Дмитрий» в естественном
варианте, если доступны для вашей сборки Windows). После установки новый голос сразу
появится в выпадающем списке на вкладке **Озвучка и чат** — перезапускать программу не
обязательно, только переоткрыть вкладку.

**Для действительно человекоподобных голосов, персонажей (робот, эффект глубокого голоса
и т.п.) и клонирования собственного голоса** штатного Web Speech API уже недостаточно —
это требует облачного TTS-провайдера (например, Yandex SpeechKit — с хорошей поддержкой
русского языка, или ElevenLabs — с клонированием голоса). Это отдельный этап разработки,
подробности — в переписке с автором проекта.



## 7. Сборка `.exe` для Windows

```bash
npm run dist
```

Команда запускает `electron-builder --win nsis` и создаёт установщик в папке `release/`
(например, `release/NeuroStream Studio Setup 1.0.0.exe`). Сборку нужно выполнять на Windows
(или в CI на `windows-latest` — см. `.github/workflows/build-windows.yml`, который делает это
автоматически при пуше в репозиторий и публикует готовый `.exe` в разделе Releases).

Иконка приложения лежит в `build/icon.ico` — это временная заготовка (простой неоновый
монограммный логотип), замените её на свой файл при желании.

## 8. Структура проекта

```
src/
  main/            Electron main process (main.js, preload.js)
  server/
    db/            SQLite: схема (schema.sql), подключение (database.js), репозитории (repos.js)
    services/      Вся бизнес-логика: TikTok/AxelChat коннекторы, TTS-очередь, триггеры,
                    IoT, медиатека, фильтр мата, монитор ресурсов
    routes/api.js  REST API
    index.js       Сборка сервера: Express + Socket.io + все сервисы вместе
  renderer/
    index.html     Панель управления (6 вкладок)
    overlay.html   Страница для OBS Browser Source
    tts-host.html  Скрытая страница синтеза речи (Web Speech API)
    css/, js/      Стили (4 темы) и клиентская логика по вкладкам
build/             Ресурсы для electron-builder (icon.ico)
```

## 9. Известные ограничения / что можно улучшить дальше

- Иконка (`build/icon.ico`) — базовый placeholder, стоит заменить на финальный логотип.
- Синтез речи использует голоса, установленные в Windows (через Web Speech API Chromium) —
  см. раздел 6 про быстрое улучшение и про облачные голоса/клонирование.
- Прямого встроенного OAuth-входа в YouTube/Twitch/Kick/VK Видео пока нет — сейчас эти
  платформы подключаются через AxelChat (раздел 5), что уже даёт единый поток сообщений
  со всех них. Отдельная нативная авторизация для каждой платформы (без AxelChat) —
  большая отдельная задача, есть смысл делать только под конкретную платформу, если
  подключение через AxelChat почему-то не устраивает.
- Через AxelChat донаты/подписки пока распознаются как обычные сообщения чата (см. раздел 5) —
  точная классификация "это донат" под каждую платформу требует проверки на реальных данных.
- Голоса «Робот», «глубокий голос» и клонирование собственного голоса не реализованы —
  требуют облачного TTS-провайдера (раздел 6).
- Сворачивание в системный трей не реализовано — сейчас закрытие окна завершает приложение.
- Drag-and-drop переупорядочивание действий триггера реализовано кнопками ↑/↓
  (без визуального перетаскивания мышью).

## 10. Лицензия

Внутренний проект — распространение и лицензирование определяются владельцем.
